# Custos Managed Storage

Custos provides managed storage capabilities for ATB bundles and receipts, offering both filesystem-based and S3-compatible object storage options. This allows for centralized custody of tamper-evident traces generated by ATB clients.

## Storage Backends

Custos supports the following storage backends:

### Filesystem Storage (Default)

This is the default storage mechanism, where bundles and receipts are stored directly on the local filesystem of the Custos daemon.

**Configuration Flags for `custosd`:**

*   `--worm-dir <path>`: Directory for immutable ATB bundle storage (default: `~/.atb/custos/worm`).
*   `--receipt-dir <path>`: Directory for receipt JSON storage (default: `~/.atb/custos/receipts`).
*   `--receipt-max-age-days <n>`: Maximum age in days for receipts (0 for no limit). Old receipts will be automatically cleaned up.
*   `--receipt-max-count <n>`: Maximum number of receipts to keep (0 for no limit). Oldest receipts will be removed if the count exceeds this limit.
*   `--cleanup-interval <duration>`: Interval for running retention policy cleanup (e.g., `1h`, `30m`, `0` to disable).

**Example `custosd` startup with filesystem storage and retention:**

```bash
custosd \
  --worm-dir /var/lib/custos/worm \
  --receipt-dir /var/lib/custos/receipts \
  --receipt-max-age-days 30 \
  --receipt-max-count 10000 \
  --cleanup-interval 1h
```

### S3-Compatible Object Storage

Custos can also store bundles and receipts in an S3-compatible object storage bucket. This is useful for scalable, highly available, and durable storage.

**Configuration Flags for `custosd`:**

*   `--s3-bucket <name>`: S3 bucket name for storage (required for S3 storage).
*   `--s3-region <region>`: AWS region for the S3 bucket (e.g., `us-east-1`).
*   `--s3-endpoint <url>`: Optional. Custom S3 endpoint URL, useful for S3-compatible services like MinIO or localstack.
*   `--receipt-max-age-days <n>`: Maximum age in days for receipts (0 for no limit).
*   `--receipt-max-count <n>`: Maximum number of receipts to keep (0 for no limit).
*   `--cleanup-interval <duration>`: Interval for running retention policy cleanup.

**Important:** You cannot configure both filesystem and S3 storage simultaneously.

**Example `custosd` startup with S3 storage and retention:**

```bash
custosd \
  --s3-bucket my-atb-custody-bucket \
  --s3-region us-west-2 \
  --receipt-max-age-days 90 \
  --cleanup-interval 6h
```

## ATB client integration

ATB CLI commands can lodge a completed bundle with a running Custos daemon.
Custos ingests whole bundles, not individual events or derived evidence packs.
It verifies the bundle before persisting it and returns a signed custody
receipt.

Keep `ATB_CUSTOS_TOKEN` in the environment or a local secret manager. Do not put
real bearer tokens in committed scripts, docs, or config files.

### `atb intercept`

While intercepting, the completed bundle is pushed to Custos when each session
closes.

**Configuration flags for `atb intercept`:**

*   `--custos <url>`: The URL of the Custos ingest endpoint (e.g., `http://localhost:9090`).
*   `ATB_CUSTOS_TOKEN`: Optional environment variable supplying the Bearer token for Custos.

**Example:**

```bash
ATB_CUSTOS_TOKEN="<custos-bearer-token>" atb intercept \
  --port 8080 \
  --bundle /tmp/my-local-bundle.atb \
  --target openai \
  --custos http://localhost:9090
```

Captured events are appended to `/tmp/my-local-bundle.atb`, and the bundle is
pushed to Custos when the session closes.

### `atb incident export`

`atb incident export --custos-endpoint` lodges the authoritative bundle with
Custos and prints the signed receipt. Use `--out` instead to write a local
offline evidence package. The two are mutually exclusive.

**Configuration flags:**

*   `--custos-endpoint <url>`: The URL of the Custos ingest endpoint (e.g., `http://localhost:9090`).
*   `--custos-auth-token <token>`: Optional. Bearer token for Custos. Can also be set via `ATB_CUSTOS_TOKEN`.

**Example:**

```bash
ATB_CUSTOS_TOKEN="<custos-bearer-token>" atb incident export \
  --bundle /path/to/my-agent.atb \
  --session sess_abc123 \
  --custos-endpoint http://localhost:9090
```

### `atb compliance pack`

`atb compliance pack` writes a local offline evidence package with `--out`. It
does not push to Custos: the pack is a derived artefact, and Custos takes custody
of bundles, not packs. To lodge the underlying bundle with Custos, use
`atb incident export --custos-endpoint` or `atb intercept --custos-endpoint`.
