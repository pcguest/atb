# ATB v1.16 CLI and View treatment

> Historical supporting evidence for the local candidate work. This document
> records the command-to-View boundary; it does not certify the current
> candidate or authorise further implementation or release steps.
> Current status: [local product convergence](./v1.16.0-product-convergence.md).

This matrix records the user-facing command audit for the local investigation
view. The View keeps recorded evidence read-only except for the two server
operations which already exist with role and integrity guards. It does not
turn command flags, filesystem paths, or external side effects into buttons.

| CLI capability | Treatment | View behaviour and boundary |
| --- | --- | --- |
| `verify` | Direct View action | **Verify bundle** is available in the **Verify** palette group and calls the existing `POST /api/v1/bundle/verify` endpoint. It retains the operator role and verified-integrity checks; pending and failure results are announced. |
| `incident list` | Visual representation | The Incident, Findings, and Timeline surfaces present the recorded investigation and its exact supporting event links. The CLI remains the way to enumerate and script session lists. |
| `incident report` | CLI-only by design | The command renders portable Markdown, JSON, or NDJSON reports. The View presents the same investigation evidence but does not manufacture or download a report. |
| `evidence` | Visual representation | Evidence and Timeline show exact records, identifiers, hashes, canonical record data, and copy actions. `atb evidence` remains suitable for structured text/JSON output and evidence packs. |
| `profiles` / profile selection | Visual representation | The selected profile and its recorded assessment appear in Trust. Profile discovery, validation, custom profile paths, and profile flag handling remain CLI-only. |
| `trust-report` | Visual representation | Trust presents integrity, coverage, corroboration, signature, anchor, custody, canonicalisation, boundaries, and source-event links. The CLI remains the formatter for text, Markdown, and JSON trust reports. |
| `export` | CLI-only by design | Export writes portable archive artifacts and can include configuration, reports, and checksums. No export endpoint exists in the local View API. |
| `reveal` | Direct View action | A masked field can be revealed from its exact event. The existing `POST /api/v1/privacy/reveal` endpoint enforces role, reveal authentication, rate limits, and integrity, and records to the independent reveal sidecar. |
| `anchor` | CLI-only by design | Anchoring contacts a configured RFC 3161 TSA and appends evidence. The View can show recorded anchor status; it does not initiate an external timestamping operation. |
| `corroborate` | CLI-only by design | Corroboration fetches an external receipt and appends a record. The View shows recorded corroboration and exact sources; it does not fetch or create corroboration. |

The command palette uses only these View groups: **Navigate**, **Inspect**,
**Verify**, **Export**, **Copy**, and **Open raw evidence**. A group is absent
when the current local View session has no supported operation in it. In
particular, **Export** is intentionally not populated because the viewer API
does not provide a safe archive-export operation.

Evidence: CLI command dispatch and usage are in `cmd/atb/main.go`; the View
API registers only verification and privacy-reveal mutations in
`pkg/api/v1/handlers.go`; the UI actions are in
`web/app/view/page.tsx` and `web/app/view/components/CommandPalette.tsx`.
